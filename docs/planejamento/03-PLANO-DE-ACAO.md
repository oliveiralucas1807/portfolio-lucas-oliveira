# Plano de ação

## Fase 0 — concluída nesta preparação

- localizar fonte canônica;
- confirmar commit publicado;
- criar backup Git completo;
- criar ZIP do código publicado;
- criar cópia independente sem remote;
- consolidar pesquisa e escopo.

## Fase 1 — auditoria visual da V1

- capturar desktop e mobile;
- medir hero, cards, tipografia e espaçamento;
- identificar componentes preserváveis;
- listar problemas reais;
- definir baseline de desempenho e acessibilidade.

## Fase 2 — sistema visual compartilhado

- paleta;
- tipografia;
- tokens de espaçamento;
- largura de conteúdo;
- grid;
- botões;
- cards;
- topbar;
- tratamento de imagens;
- motion tokens.

Entregável: documento visual ou Figma antes de alterar toda a página.

## Fase 3 — decisão técnica

Comparar:

1. evoluir HTML/CSS/JS atual;
2. migrar a V2 para Astro + Tailwind.

Direção preferida: Astro + Tailwind, desde que um protótipo com hero, card e
mini-case prove que a migração não aumenta desnecessariamente a complexidade.

## Fase 4 — protótipo mínimo

Implementar somente:

- topbar;
- hero;
- um card;
- um mini-case;
- faixa com poucas imagens.

Validar desktop, mobile, teclado, redução de movimento e build.

## Fase 5 — migração da V2

- estruturar todos os projetos;
- migrar Sobre;
- integrar currículo;
- concluir contato;
- otimizar imagens;
- revisar SEO;
- revisar acessibilidade.

## Fase 6 — pré-publicação

- build limpo;
- preview local;
- links;
- imagens;
- console;
- 404;
- Lighthouse;
- screenshots;
- comparação V1/V2;
- aprovação de Lucas.

## Fase 7 — publicação

Somente após aprovação:

- definir estratégia de repositório;
- configurar GitHub Pages;
- criar checkpoint final da V1;
- publicar;
- validar a URL;
- manter rollback documentado.

## Fase 8 — integração com cases

- selecionar um case piloto;
- definir URL;
- adicionar link no Light;
- validar continuidade visual;
- documentar o fluxo de atualização.
